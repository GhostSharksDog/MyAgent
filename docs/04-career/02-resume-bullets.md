# 简历条目与证据（AI 应用 / Agent 开发）

项目名称：**Legacy · 手写内核的通用 AI Agent**。
个人项目，Python 3.12 / FastAPI / React 19 / TypeScript / Redis / SQLite。

## 可直接使用的三条

- 手写 OpenAI 兼容客户端与 Agent 内核，实现流式 tool_calls 分片重组、ReAct、
  Plan-and-Execute 与 Supervisor；三种编排共用工具层、单轮 deadline、上下文预算与用量账本，
  修复子任务配置丢失、规划/汇总绕过超时及 Supervisor token 上限失效。
- 完善请求取消与副作用控制：SSE 断开时关闭生成器，取消并等待全部专家；同一注册表的写操作
  跨专家/请求互斥，只读工具继续并发；预算退出保留部分结论并标记非成功，缺 Usage 明确报告统计不完整。
- 建立公开样本 RAG 消融、离线回归与 Windows CI；14 条查询、k=5，RRF 混合召回 Recall@5
  **0.821 → 0.869**，特征重排 MRR **0.601 → 0.685**。当前模型上三种编排、预算与取消
  累计 **26 次受限 HTTP 尝试**验证，最多 512 输出 token/次，无自动重试，未改用户配置文件。

两条精简版：保留前两条，第三条中的 RAG/验证数字放在项目介绍末尾。
测试数量只有在最后一次门禁通过后填写，并标注日期；不要把数量增长写成业务质量提升百分比。

## 数字溯源

| 数字 | 条件与出处 | 能证明什么 |
|---|---|---|
| Recall 0.821 → 0.869 | `eval_rag.py --compare --sample`；公开 seed；14 查询；section/min_size120；k5 | 同一小样本中混合召回的增量 |
| MRR 0.601 → 0.685 | 同一消融，向量与向量+特征重排 | 排序改善；不能忽略重排降低召回的负结果 |
| 26 次 | `verify_agent_modes.py` 的 HTTP 钩子计数，含失败与脚本中断前的尝试 | 受限真实验证规模；不等于 26 个任务成功 |
| 0 遗留专家 | 真实取消报告及 ASGI disconnect 回归 | 当前单进程请求的任务清理 |
| token 用量 | [证据表](../05-reliability-evidence.md)中的已知 Usage 与完整标记 | 当前输入的用量；未知部分不能视为 0 或换算费用上限 |

## 面试中准确描述边界

“我把三种编排的时间、配置、成本和取消路径统一起来，再用反例证明预算不会被子任务重领。
互斥覆盖同进程共享注册表；同步写入取消时必须等待线程完成，不能回滚。
token 阈值按已返回 Usage 检查，在途可能超额；不完整用量会显式展示。
公开 RAG 指标是 14 条查询的小样本，下一步需要扩充评价集与标定真实模型 P95。”

CI 配置已实现，本地等价检查已跑；远端首次绿色结果待用户推送确认。
PostgreSQL/pgvector、生产部署收尾、真实阈值标定仍是计划；不使用“生产级”“用户成功率”等未验证表述。
