> 2026-10-06：当前求职方向为 AI 应用 / Agent 开发，项目定位是通用助手。
> 一页纸、简历条目和演示脚本已更新；历史 STAR/问答保留原案例，新可靠性补充置于文首。
> 最新数字与未验证项见 [可靠性证据](../05-reliability-evidence.md)。

> 这一目录的验收标准是**可执行的**，不是"写完了"。见每份文件开头的验收说明。

| 文件 | 用途 | 验收方式 |
|---|---|---|
| `01-onepager.md` | 项目一页纸 | **找个没参与过项目的人读 5 分钟**，能说清做什么、亮点是什么 |
| `02-resume-bullets.md` | 简历条目（含数字溯源表） | 每个数字都能**当场跑命令复现** |
| `03-star-stories.md` | 6 个 STAR 故事 | 每个能讲 90 秒；S/T 各 15 秒、A 占 45 秒、R 用 15 秒给数字 |
| `04-technical-qa.md` | 31 题技术深挖问答 | 每行掐表 90 秒不看资料讲完；🟢 的题目能指到具体代码 |
| `05-demo-script.md` | 3 分钟演示脚本 | **断网状态下也能跑完**（`scripts/verify_demo.py` 断言） |

## 使用顺序

**面试前一天**：
1. 跑一遍 `05-demo-script.md` 的"演示前 60 秒检查"，确认 `/healthz` 的 `demo_replay` 不是 `off`
2. 把 `04-technical-qa.md` 逐行过一遍，掐表
3. 挑岗位最相关的 3 个 STAR 故事重点准备

**面试时**：
- 开场用 `01-onepager.md` 的一段话
- 演示严格按 `05-demo-script.md` 的时间分配
- 被问到不会的问题 → 主动引导到 🟢 区域（`04-technical-qa.md` 末尾有具体话术）

**面试后**：
- 被问倒的问题补进 `04-technical-qa.md`，并标注当时是哪种失败（不知道 / 知道但讲不清 / 讲错过）
- **讲错过的最值得补** —— 那是真实的知识缺口

## 三份材料之间的关系

```
01-onepager      → 面试官第一眼看的东西，决定他有没有兴趣往下问
     ↓
02-resume-bullets → 他决定问了，会照着简历条目问
     ↓
03-star-stories   → 追问"具体怎么做的" → 讲 STAR
     ↓
04-technical-qa   → 再往深挖 → 逐题答，且知道自己的边界在哪
     ↓
05-demo-script    → "能不能现场看看" → 演示
```

**每一层都在为下一层做准备。** 一页纸写得再好，简历条目里的数字复现不了，
第二层就塌了 —— 而面试官一旦发现一个数字是编的，会**默认所有数字都是编的**。

---

## 一条底线

这一目录里出现的**每一个数字**都必须能追溯到某个文件、某份报告或某次压测输出。
`02-resume-bullets.md` 的"数字溯源表"就是为此存在的：
面试时被追问"这数字怎么来的"，可以当场打开跑给他看。

**答不上来的数字比不写更糟** —— 它会污染你其它真实数字的可信度。
