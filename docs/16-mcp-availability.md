# MCP 已连接却不可调用：名称匹配与状态查询修复

2026-10-08，用户报告 Windows 发行包中 Tavily 显示已连接，但模型仅看到计算、时间、知识检索和记忆工具。
通过当前本机实例的只读管理接口复现：连接正常；旧预设选择 `tavily-search`、`tavily-extract`，服务实际发现 `tavily_search`、`tavily_extract`，没有任何名称匹配。
因此工具没有进入共享注册表，模型未收到联网工具定义。连接成功与工具可用是不同状态。

## 修复与兼容

- Tavily 新预设及公开配置样例改用远程实际发现的下划线名称。
- 连接时兼容旧 Tavily 选择：只有原名称不存在且对应新名称确实被发现时，替换已选择的搜索/提取工具；不添加其它工具，不转移旧只读信任，不修改密钥。
- MCP 查询增加 `available_tool_count`、`missing_tools`，前端同时显示连接与可用工具数。缺失工具给出高级设置的刷新/选择入口。
- 三种编排共用 `get_mcp_status`，即使 MCP 关闭或没有服务也可查询；它只读取当前本机状态，不连接远端，不回传地址、鉴权、进程参数或环境变量。
- 外部 MCP 可用时，提示词不再绝对声称不能运行 shell。是否可以执行以实际工具定义和用户逐次批准为准，内置 `run_terminal` 权限继续独立。
- 现有 MCP 保存接口接受新增只读状态字段但忽略它们，保留原有配置往返兼容。

当前用户实例仅修正了原有 Tavily 工具选择，通过 `/api/tools` 确认两项外部工具已注册。
没有执行搜索、网页提取、终端命令或真实模型请求，没有改写源码 `.env`，也没有自动开启终端权限。

## 终端如何启用

两条入口任选其一，均需明确目录与确认：

1. 设置 → MCP → 添加 Desktop Commander，填写现有允许目录，保存并连接；应显示可用工具。命令调用会展示服务、工具及完整参数，用户批准后运行。
2. 设置 → 工作区，选择目录，显式开启本机终端并保存。模型下一轮收到 `run_terminal`，每条命令仍需批准。

当前实例诊断时只配置了 Tavily，Desktop Commander 不在服务列表，内置终端开关为关闭。
联网服务连接不顺带启用本机终端；目录不是终端沙箱。

## 验证

新增回归直接检查模型收到的工具定义和状态工具返回消息，覆盖旧名称修正、持久化、选择范围、旧信任失效、自定义服务不改名、原名称仍存在时保留、配置目录写入失败和脱敏状态。
Edge 夹具使用 Tavily 实际发现名称，替代此前所有预设都返回 Exa 工具的模拟；断言预设与发现匹配，以及已连接但零可用工具的可操作提示。
