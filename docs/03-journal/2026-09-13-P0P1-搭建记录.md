## 二、踩的坑（这是今天最有价值的部分）

### 坑 1：`PIP_TARGET` 让虚拟环境彻底失效 ⭐ 最坑

**现象**：`pip install` 报了 `Successfully installed fastapi-0.141.1 ...`，但 `.venv` 里只有 `pip` 一个包，`import fastapi` 照样 `ModuleNotFoundError`。同时报错：

```
PermissionError: [WinError 5] 拒绝访问:
  ... -> 'E:\Python\Python39\Lib\site-packages\annotated_doc'
```

**排查过程**：一开始我怀疑是网络慢，实测各镜像索引页都在 1 秒内返回；也怀疑过换 `pip3`，但 `pip3.exe` 就在 `E:\Python\Python39\Scripts\` 下，撞的是同一堵墙。最后查环境变量才找到真凶：

```
PIP_TARGET = E:\Python\Python39\Lib\site-packages   ← 用户级环境变量
```

**原理**：`PIP_TARGET` 会指定 pip 的安装目标目录，**它的优先级高于虚拟环境**。只要它在，无论 `pip`、`pip3`、还是 `.venv\Scripts\python.exe -m pip`，装出来的东西全都进 Python 3.9 的 site-packages，venv 的隔离形同虚设。

**解法**：安装前 `Remove-Item Env:PIP_TARGET`（只影响当前进程，不动全局配置）。

**教训**：`Successfully installed` 不等于"装到了你期望的地方"。装完必须用 `python -c "import xxx"` 验证，而不是相信 pip 的输出。

### 坑 2：pip 缓存目录被文件沙箱拒绝，导致 CPU 空转

**现象**：第一次装依赖时，一个 python 进程烧了 **348 秒 CPU**，却一个包都没落地；第二次直接卡死 7 分钟。

**排查**：逐个测试目录写权限，发现

```
WRITABLE  C:\Users\LCY\AppData\Local\Temp\dsh-ZR3V09
DENIED    C:\Users\LCY\AppData\Local\pip\Cache        ← 元凶
WRITABLE  D:\WXP\简历\MyAgent\.pip-cache
```

**原理**：pip 每次下载都想往 HTTP 缓存里写，写入被拒后它在重试/降级逻辑里反复挣扎，表现为 CPU 高占用 + 零进展。

**解法**：`$env:PIP_CACHE_DIR = "$PWD\.pip-cache"`，把缓存重定向到工作区内。**同一份解析从 7 分钟降到 4.5 秒。**

---

### 坑 3：PowerShell 把 `.env` 的中文写成了乱码

**现象**：`.env` 生成后 `is_configured=False`，密钥读不到。逐行 dump 发现：

```
1| '\ufeff# ============...'
2| '# Legacy \ue21a\ue568配置模板'      ← 应该是「环境配置模板」
```

**原理**：Windows PowerShell 的 `Get-Content` 默认按系统代码页（中文系统是 GBK）解码文件。用它读 UTF-8 文件再回写，中文就变成私有区乱码字符。同时控制台 stdout 也是 GBK，Python 打印中文直接 `UnicodeEncodeError`。

**解法**：把这件事交给 Python 做，全程显式 `encoding="utf-8"`，并且**不写 BOM**（BOM 会让 dotenv 把第一行解析成一个诡异的键名）。顺手把它固化成了项目脚本 `scripts/bootstrap_env.py`。

**教训**：**不要用 shell 做文本处理**。涉及编码、密钥、多语言内容的文件操作，一律用目标语言自己的 IO 显式指定编码。

### 坑 4：测试抓出的计算器浮点 bug

```python
# 修复前
"(12000*12)*0.8"  →  "= 115200.00000000001"     # IEEE 754 表示误差
"0.1+0.2"         →  "= 0.30000000000000004"
```

这个 bug 的严重性不在"算错了"，而在**工具的输出会被模型原样念给用户**。用户看到一串莫名其妙的尾数，会直接判定这个 Agent 不可用。

**解法**：`_clean_number()` 按 10 位小数修约，修约后是整数则转 `int`。既消除二进制噪声，又不误伤真实精度。

**教训**：这是"写测试才发现的问题"的典型例子——手工点几下测不到，因为没人会去输入 `(12000*12)*0.8` 看尾数。

### 坑 5：嵌套 `BaseSettings` 不继承父级的 `env_file`

```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=PROJECT_ROOT / ".env")
    llm: LLMSettings = Field(default_factory=LLMSettings)   # ← 读不到 .env
```

**原理**：pydantic-settings 里，嵌套的 `BaseSettings` 字段由它**自己的** `model_config` 实例化，不会继承父级的 `env_file`。所以 `.env` 里的 `LLM_API_KEY` 永远读不进来，表现为"我明明写了 .env 却说没配密钥"。

**解法**：给 `LLMSettings` 和 `AgentSettings` 各自声明 `env_file`。已在代码里写了醒目注释防止后人再踩。

---

### 坑 6：在 async 函数里调 `input()` 会阻塞事件循环

ruff 的 `ASYNC250` 报出来的。单用户 CLI 里看不出问题，但在任何有并发任务的场景下，整个进程会卡死——定时器、心跳、其他协程全部停摆。

**解法**：`await asyncio.to_thread(input, prompt)`。

**教训**：`ASYNC` 这一类 lint 规则值得开。它抓的是"能跑但会在生产环境炸"的问题。

## 三、设计上刻意的取舍

| 决策 | 理由 | 代价 |
|---|---|---|
| 手写循环，不用 LangChain | 目标是讲清协议与循环；框架会隐藏 `tool_calls` 配对、流式分片这些面试必问点 | 少了现成的生态与抽象 |
| 工具失败转"观察结果"而非抛异常 | 模型看到错误能自我修正（参数名写错、少必填字段），这是 Agent 与"调一次 API"的本质区别 | 错误可能被模型忽略，需要提示词配合强调 |
| 只用白名单 AST 算计算器 | 参数来自模型→等同用户输入，`eval()` 等于开放远程代码执行 | 表达能力受限（不支持变量、自定义函数） |
| 历史只存 user/assistant，丢弃 tool 消息 | 工具调用是过程信息，留着只会持续烧 token | 多轮时模型记不住查过什么，P2 需要 `Memory` 模块补 |
| 模块化单体起步，不直接上微服务 | 现在拆只会增加调试成本；等到"RAG 索引构建拖慢 API 响应"这个痛点真实出现时再拆 | 后期拆分要改调用路径 |

## 四、还没做、但知道该怎么做

- **工具串行执行**：模型一次返回多个 `tool_calls` 时，互不依赖的可以 `asyncio.gather` 并发，延迟从 `n×T` 降到 `1×T`。留到 P3。
- **无鉴权、无限流、无 trace id**：现在谁都能调，且一次失败请求跨了"模型→工具→模型"多跳却没有链路追踪。P4 补。
- **无持久化**：会话历史只在内存里，进程重启即丢失。P2 接 SQLAlchemy + Redis。
- **前端还没开始**：目前只有 CLI 和裸 SSE，P3 上 React。
